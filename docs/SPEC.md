# Delivery scope

User asks to implement the supplied restaurant plan as a high-quality functioning local demo with Rust backend/business logic, Vuetify UI, Capacitor Android/iOS projects, owner-specific menus and a public GitHub repository with build/test workflows. No hosting, domain or deployed backend is requested. Prefer autonomy and reasonable defaults; do not block on routine preference questions.

Critical acceptance: menu separation between owners; guest table visit is current and not another party’s historical visit; guest request requires staff approval; trusted prices and no duplicate retries; kitchen item progress; cash bill settlement and closure; local durable persistence; real optional Rust API; mobile project/build pipeline. Label sample data, demo roles, unconnected payments and unsigned iOS artifacts honestly. Document partial long-term features and production prerequisites.

Visual direction: warm ivory, dark botanical green, editorial food photography, restrained typography, generous spacing, calm restaurant-specific controls. No generic neon/gradient dashboard styling. Guest and staff views have distinct hierarchy.
